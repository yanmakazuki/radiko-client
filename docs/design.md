# Rust製radiko TUIクライアントの設計

## 目的と初期版の範囲

macOSのターミナルから、全国の番組をジャンル・出演者分類・キーワードで探し、そのまま再生できるクライアントを作る。

- ライブと過去30日のタイムフリーに対応。
- 公式Webにログインできるダブルプラン契約を前提にする。
- 「女性アイドル」などの検索条件を名前付きで保存する。
- タイムフリー番組の公式AIチャプターを表示し、選択した位置から再生する。取得方法は公開実装を参考に実通信で検証する。
- 音声デコードも純Rustとし、外部プレイヤーを使用しない。
- 録音、ポッドキャスト、通知、再生位置の保存は初期版に含めない。

新規プロジェクトとして開始する。実装上の責務・データモデル・状態遷移・非同期処理は[アーキテクチャ設計](architecture.md)に定義する。

## 番組一覧CLIの先行実装（2026年10月15日）

ユーザーの番組一覧取得の要望を受け、音声出力の完成前に単一局・単一放送日の`programs STATION [YYYYMMDD] [--json]`を提供する。日付省略時は午前5時区切りの当日とし、ログイン不要で毎回取得する。放送前番組、空分類、未知分類、分割枠を保持し、取得時点の放送状態と「再生可否未確認」を表示する。地域・全国の指定として`programs --areas JP13,JP14 [YYYYMMDD] [--json]`と`programs --all [YYYYMMDD] [--json]`も提供する。47都道府県の地域別局一覧を取得し、選択地域の和集合を局IDで重複排除してから1日分の番組表を最大4並列で取得する。テキストは局単位で順次表示し、JSONは最終結果をまとめる。地域・局の未取得や不正枠除外があれば部分結果として明示し、終了コード1とする。分類・キーワードのCLI検索は2026年10月16日の節を参照。期間指定も2026年10月16日の節を参照。検索条件保存は末尾のCLI節を参照。TUI、自動状態更新は後続の範囲とする。

## 構成とデータ設計

単一のCargoプロジェクトで、次の責務をモジュールに分ける。

| モジュール | 責務・採用技術 |
|---|---|
| `radiko` | `reqwest`による番組表・会員認証・配信情報取得、`quick-xml`によるXML解析 |
| `catalog` | 取得した番組・分類の正規化と全国検索 |
| `player` | HLS取得、コンテナ解析、`rusty_aac`によるADTS/AAC・SBRデコード、Symphoniaによるその他サンプル解析、CPALによる音声出力 |
| `ui` | Ratatui＋Crosstermによる画面とキー操作 |
| `app` | Tokioによる非同期処理、検索・認証・再生状態の管理 |
| `domain` | 放送枠・日時・検索条件・チャプター・聴取可否の共通型と判定 |
| `storage` | セッションと検索条件の読み込み・原子的保存 |

- 放送枠は「放送局ID＋開始日時」で識別する。同じ番組IDを持つ分割枠も個別に扱う。
- 日時は日本時間で扱い、放送日は午前5時を境界にする。
- 番組ジャンルと出演者分類は別フィールドに保存する。ID・名称を取得データから集計し、今回見つかった一覧を固定値にしない。
- 空の分類は「未分類」として残す。タグ・出演者名・番組説明もキーワード検索対象にする。
- 内部インターフェースは、番組表取得、条件検索、再生要求、再生状態通知に分ける。HTTPや音声処理を画面から直接呼ばない。

## 番組探索とTUI

画面は、上部に検索条件、中央に番組一覧と詳細、下部に再生状態・操作案内を配置する。

- 「ライブ」「タイムフリー」の2画面。起動時の初期画面は毎回タイムフリーとし、日付は保存済みの条件にかかわらず当日に戻す。地域・ジャンル・出演者分類・キーワードは前回の条件を復元し、初回は全国・分類指定なし・キーワードなしとする。
- 「当日」は日本時間の午前5時区切りのradikoの放送日とする。午前0時から5時未満の起動では前日の放送日、それ以外はその日の放送日を表示する。タイムフリーでは過去30日の範囲から日付・期間を選ぶ。
- 当日分には放送前の番組も表示する。日本時間の現在日時と開始・終了日時から「放送前」「放送中」「放送終了」を判定し、文字ラベルで区別する。放送前の番組は詳細を閲覧できるが再生できず、再生操作時は「放送前のため再生できません」と表示し、現在の再生を継続する。
- 放送状態は時間の経過に合わせて通信なしで更新する。放送状態と聴取可否は別に扱い、放送終了だけを理由に再生可能とは判定しない。契約・配信対象・聴取期限に応じた再生可否と理由を表示し、未確認の場合は「再生可否未確認」とする。
- 絞り込み条件は日付、地域、ジャンル（番組ジャンル）、出演者分類、キーワードの5項目とする。日付は単日または期間で指定する。異なる条件間はAND、同じ分類内の複数選択はOR。
- 検索条件は入力中の値と確定済みの値を分けて管理する。入力・選択の変更だけでは通信せず、検索条件画面の「検索」操作で確定したときに取得する。検索条件画面の`Enter`は検索確定、番組一覧の`Enter`は再生とする。編集をキャンセルした場合は確定済みの条件を維持する。
- 検索中も現在の再生を続ける。条件編集・検索確定・取得失敗でプレイヤーを停止または切り替えない。検索取得と再生用通信は独立して扱い、新しい検索を確定した場合は古い検索処理をキャンセルし、その結果を新しい一覧へ反映しない。
- 地域の絞り込みは「その地域で聴ける局」を対象にする。地域別の局一覧から対象局を決定し、同じ局が複数地域に含まれる場合は局IDで重複排除する。番組一覧も「放送局ID＋開始日時」で重複排除する。同じ番組を別の局が放送する場合や、開始日時が異なる分割枠は別々に表示する。
- 全国の局一覧を取得して局IDを重複排除し、選択期間の番組表を局単位で取得する。初回から全国30日分を一括取得しない。
- 取得は最大4並列。結果を順次表示し、取得済み局数・失敗局数を明示する。取得途中の件数を全国の確定件数として表示しない。
- 番組表・局一覧・分類一覧のキャッシュは使用しない。起動時、検索条件の確定時、手動更新時に必要なデータを取得する。処理中の検索・表示に必要なデータのみメモリに保持し、次の取得を省略するために再利用しない。取得失敗時は未取得の範囲と再試行操作を表示する。
- 検索条件は保存・呼び出し・削除に対応。名前付き条件を明示的に呼び出す場合は保存した日付・期間も適用する。起動時の自動復元では日付を当日に戻し、地域・ジャンル・出演者分類・キーワードのみ復元する。

キー操作は、`Tab`で領域移動、上下矢印／`j k`で選択、`/`で検索、`f`で絞り込み、`Enter`で再生、`Space`で一時停止、`s`で停止、左右矢印でタイムフリーを15秒シーク、`+ -`で音量、`?`でヘルプ、`q`で終了とする。ライブの再開は最新位置へ戻る。

## タイムフリーのチャプター

公式AIチャプターのタイトルと開始位置を番組詳細に表示し、選択した箇所からタイムフリーを再生する。独自の文字起こし・AI生成は行わない。ポッドキャストは初期版の対象外のままとする。

### 取得方法と参考実装

2026年10月15日に公開コードを確認した。[yt-dlp-rajiko v1.14](https://github.com/garret1317/yt-dlp-rajiko/releases/tag/v1.14)はradikoのAIチャプターに対応しており、[取得処理](https://github.com/garret1317/yt-dlp-rajiko/blob/master/yt_dlp_plugins/extractor/radiko.py#L493)では番組情報の`eventId`を用いて次のURLからJSONを取得する。

```text
GET https://api.annex-cf.radiko.jp/v1/programs/{eventId}/chapters
```

| JSONフィールド | 公開実装での用途 |
|---|---|
| `chapters` | チャプターの配列 |
| `titleLong` / `title` | タイトル。`titleLong`を優先 |
| `fromSec` | 開始位置（秒） |
| `toSec` | 終了位置（秒） |
| `summaryLong` | 要約 |
| `isMusic` | 楽曲の区別。参考実装はAIチャプター抽出時に楽曲を除外 |

[rfriends3の更新履歴](https://rfriends.github.io/rfriends/ver.html)にも1.6.3系でタイムフリーのチャプター対応が記載されている。

2026年10月16日に、本プロジェクトでTBSの前日・10日前の分割枠についてメタデータとチャプター取得を確認した（下記CLI節）。当該対象では認証ヘッダーなしで取得できたが、全番組の認証条件や音声原点を保証しない。公式に保証された外部向けAPI仕様としては扱わない。秒数と実音声の対応、他局・異なるイベント原点への対応は引き続き検証する。番組表XMLの番組IDが`eventId`と同一だと仮定せず、別フィールドで保持する。ブラウザ版にチャプター表示があることは前提にしない。

### 取得・表示・再生

- `radiko`がチャプターJSONを取得・解析し、`app`が取得状態を管理、`ui`が表示する。`player`は通常のタイムフリーシークと同じ経路で開始位置を受け取る。
- 番組詳細で`c`を押すとチャプター一覧を開き、その時点で対象番組分だけ取得する。全国検索での一括取得や永続キャッシュは行わず、一覧を開き直す場合や手動更新時は再取得する。
- 上下矢印／`j k`で選択し、`Enter`で対象番組のチャプター開始位置から再生する。`Esc`で詳細へ戻る。再生中の番組と一致する場合は出力済みPCMに基づく再生位置から現在のチャプターを強調する。
- 詳細で選択中の番組と再生中の番組を、それぞれ番組名・放送局・放送日時で明示する。詳細の閲覧やチャプター一覧の選択移動だけでは再生を切り替えない。同じ放送枠のチャプターを`Enter`で確定した場合はシークし、別の放送枠の場合は対象番組へ切り替えて指定位置から再生する。放送枠の一致判定には「放送局ID＋開始日時」を使う。
- 内部では開始・終了位置を番組冒頭からの経過時間として扱い、APIの時刻基準を実通信で確認して変換する。開始位置が負数・非数・放送枠末尾以降の項目や、終了位置が開始位置以下・放送枠外の項目はジャンプ対象にしない。不正な項目があることを表示し、有効な項目を開始位置順で扱う。
- 「取得中」「チャプター未提供」「取得失敗」「番組との対応付け未確認」を区別する。成功した空配列は生成待ちの可能性もあるため未提供と表示する。空配列と通信失敗を同じ表示にせず、失敗時は再取得できるようにする。番組変更時は古い取得をキャンセルし、遅れて届いた結果を別番組へ表示しない。
- 初期版は公式AIチャプターを対象とし、`isMusic=true`は除外する。オンエア曲を別APIから追加しない。現在チャプターは開始以上・終了未満で判定し、隙間では強調しない。重複時は開始位置が最も後の項目、同開始なら元配列で先の項目を優先する。
- チャプター取得・取得失敗では現在の再生を停止しない。チャプターがなくても通常の再生と15秒シークは使用できる。
- チャプターの存在は聴取権限を意味しない。ジャンプ再生にも通常の放送状態・契約・配信対象・聴取期限の判定を適用する。再生不可なら理由を表示し、現在の再生を継続する。ライブ位置へのジャンプは行わない。

## 認証と組込プレイヤー

- ログインは専用操作で行い、パスワードは入力をマスクし、ログ・設定ファイルへ残さない。radikoのパスワードは永続保存せず、再利用可能なセッション情報のみOSに依存しないローカルファイルに平文で保存する。暗号化と保存用パスフレーズは使用しない。
- 保存形式はバージョン付きJSONとする。保存先は`--data-dir`で指定可能にし、既定では`directories`で取得するユーザー用データディレクトリ内の`session.json`を使う。起動時に自動で読み込み、保存したセッションの有効性を確認する。セッション保存は番組データのキャッシュ禁止とは別の扱いとする。
- ファイルが存在しない場合は未ログインで起動する。読み込み失敗・ファイル破損・未対応の保存形式は理由を表示し、既存ファイルを自動で上書きせず、未ログインで番組探索を継続できるようにする。明示的な再ログインが成功した場合は新しいセッションを保存する。
- 保存は一時ファイルからの原子的置換とし、一時ファイルを含めUnixではディレクトリを`0700`、ファイルを`0600`にする。ログアウト時はメモリと保存ファイルのセッション情報を削除する。
- セッション失効時は再ログインを案内する。契約状態・番組の配信条件・サーバー応答に基づいて聴取可否を判断する。
- HLSプレイリストは`m3u8-rs`で解析する。配信データは容量上限付きメモリバッファに保持し、音声を永続保存しない。
- 通信、デコード、音声出力を分離する。CPALの音声コールバックでは通信・デコード・待機を行わない。
- 局切替・シーク時は旧処理とバッファを破棄する。再生位置は出力済みPCMから計算し、シーク先の配信取得とデコードをやり直す。
- 番組終了時は再生を停止し、次の番組へ自動で移らない。ライブは選択した番組の終了日時に達した時点で停止し、バッファに残った音声も破棄する。タイムフリーは選択した放送枠の末尾まで再生して停止する。停止時は「番組終了」と表示する。
- 通信断は最大3回の再試行後に停止し、理由を表示する。終了・異常終了時は音声停止とターミナル復元を行う。

2026年10月15日の配信取得プローブで、地元／エリア外ライブと通常／10日前のタイムフリーのHLS・先頭サンプル取得に成功した。同日、純Rustの`rusty_aac 1.1.0`をADTS経路に追加し、各先頭約5秒の全パケットについてSBRデータを検出し、コア24kHzから48kHz・ステレオのPCMを生成した。Symphoniaは非ADTS形式の検証経路として残すが、HE-AACのAACコアだけを成功扱いにしない。詳細は[実装状況](implementation.md)を参照。

**再生の成立条件の検証を継続する。** 2026年10月16日に`probe-output [SECONDS]`と`play-sample STATION [YYYYMMDDHHmmss]`を追加した。生成音と、条件確認済みのADTS先頭1セグメントをCPALで出力する。音声PCMは全パケットの検証後に最大4MiBまで保持し、2秒分の容量制限付きバッファを介して渡す。サンプル末尾で停止し、ライブでは選択枠の終了日時も上限とする。機器はPCMと同じレートのmono/stereo・f32に限り、リサンプリングやOSデコードへの代替は行わない。短い出力経路の確認と、音質・連続再生・実際の放送終了境界の検証は区別する。同日、`play-live STATION [--seconds N]`と`play-timefree STATION YYYYMMDDHHmmss [--seconds N]`に連続取得・出力を接続した。既定は選択枠の末尾まで、`--seconds`はメディア時間の上限とする。Ctrl+Cで停止する。タイムフリーは指定時刻を含む枠の冒頭から再生し、次枠へ自動移行しない。最大4MiBのPCMセグメントを容量1のキューで受け渡し、同じデコーダーと出力ストリームを維持する。HLSの重複・欠落・不連続を通し番号で検出する。短時間の実配信検証と30分連続再生・検索／TUI応答の完成条件は区別する。次はシーク・局切替とアプリイベントを接続し、長時間検証を行う。PSの明示シグナルとHE-AAC v2の実配信、CRC付き／複数raw blockのADTS、PCE構成、非ADTSのHE-AACは未検証または今回未接続。[rusty_aac 1.1.0](https://docs.rs/rusty_aac/1.1.0/rusty_aac/)を採用バージョンとして固定し、広告・仕様の対応表だけで再生対応済みとは判断しない。

実装順は、①契約認証とライブ・通常タイムフリー・8〜30日前の配信検証、②純Rustでの連続再生、③全国検索と検索条件保存、④チャプター操作を含むTUI統合とする。③ではチャプター取得と放送枠への対応付けも検証する。コンテナ解析は実配信形式に合わせて組み込み、純Rustで扱えないコーデックが必須なら、実証結果を報告して設計を再検討する。外部プレイヤーへ自動変更しない。

## タイムフリーのシークCLI（2026年10月16日）

`play-timefree`に`--offset SECONDS`と`--interactive`を追加する。対話操作は`seek 秒数`、`+15`、`-15`、`q`をEnterで確定する。相対シークの基準は出力済みPCMで、バッファ内の未出力音声や無音補填分を含めない。放送枠外とライブのシークを拒否する。`--seconds`はシーク成功後の再生にも改めて適用する。

番組の開始・終了と契約／配信条件を再確認し、HLS時刻から対象位置を確認する。直前からの約10秒のプリロールでデコーダーを準備し、指定位置より前のPCMをフレーム単位で捨てる。時刻との対応が不明なら推測で再生しない。2秒分（末尾付近は残り分）の有効PCMと新しい出力機器の準備に成功してから切替を確定する。準備中・失敗時は現在の再生を続ける。

シーク要求は最新のみ有効とし、古い準備と結果を破棄する。切替時は旧世代を停止して旧PCMを破棄し、新世代専用のキューを使う。シークは同じ局ID＋開始日時の放送枠を対象とする。対話再生での明示的な局・番組切替は次節の方式を使う。TUIのキー操作、チャプターの取得・対応付けとジャンプは後続の範囲。

## 検証・完成条件

- XML解析：空の分類、未知の分類ID、同一番組IDの分割枠、午前0〜5時の放送を正しく扱う。
- 検索：「女性アイドル」単独、音楽とのAND条件、複数分類のOR条件、条件保存・復元、全国取得の部分失敗を確認する。
- 地域：地域別の聴取可能局が対象になること、複数地域に含まれる同じ局・放送枠が一度だけ表示されること、別局の同名番組や開始日時の異なる分割枠が残ることを確認する。
- データ取得：起動・検索条件確定・手動更新で再取得され、前回のデータで取得失敗を補完しないことを確認する。
- 検索操作：条件入力・選択変更・編集キャンセルでは通信せず、確定時に取得することを確認する。検索中・検索失敗時にも再生が継続し、古い検索結果が新しい結果を上書きしないことを検証する。
- 番組状態：当日の放送前番組が表示され、開始・終了日時の境界で状態表示が更新されることを確認する。放送前番組の再生操作で配信取得や現在の再生の停止が発生しないこと、配信対象外や可否未確認を再生可能と誤表示しないことを検証する。
- 起動条件：午前4時59分は前日の放送日、午前5時は当日の放送日になること、保存済みの日付・期間は起動時に当日へ戻り、他の検索条件のみ復元されることを確認する。
- 番組終了：ライブが終了日時で停止し、タイムフリーが選択した放送枠の末尾で停止すること、次番組へ自動で移らず残った音声も出力されないことを確認する。
- 認証：ログイン成功・失敗、失効、契約不足、タイムフリー対象外を区別する。
- 認証情報保存：起動時の自動読み込み、ファイルなし・破損・未対応形式、セッション失効、保存中断、ファイル権限、ログアウト時の削除、`--data-dir`での保存先指定を検証する。保存ファイルのテストはKeychainなどOS固有の認証情報ストアに依存させない。
- 音声：セグメント境界、形式変更、バッファ不足、シーク、局切替、出力機器切断、終了処理を検証する。
- チャプター：JSONのfixtureとモックでタイトルの優先順位、空配列、不正な時刻、順序、取得失敗、古い応答の破棄を検証する。取得中・失敗時の再生継続と、ジャンプ時の聴取可否判定・旧音声破棄・放送枠末尾での停止を確認する。
- チャプターの番組切替：選択中と再生中の番組を区別して表示し、閲覧・選択移動のみでは再生が変わらないことを確認する。同じ放送枠ではシーク、別の放送枠では対象番組の指定位置から再生し、同名番組や分割枠を誤って同一視しないことを検証する。
- チャプターの実通信：`eventId`と放送枠の対応、認証条件、7日以内と8〜30日前の取得可否、チャプター開始秒数と実際の再生位置の一致を確認する。確認日・対象・手順・結果を記録し、取得できたことだけでジャンプ再生の検証済みとはしない。
- 実アカウントで地元とエリア外のライブ、7日以内と8〜30日前の対象番組を再生する。連続30分の再生中も検索・キー操作が応答することを完成条件とする。

タイムフリー30の認証・配信方式は未検証であり、対応済みとは扱わない。過去30日の聴取には対象契約が必要で、対象外番組もある。[公式の利用条件](https://help.radiko.jp/--67aeb8233df7d2ce7fe7d623)

### CLI pause and volume controls

Interactive continuous playback accepts `pause`, `resume`, and `volume 0..100`, confirmed with Enter. Default volume is 25%. Pause preserves queued audio and media position; volume zero mutes while position advances. Timefree resume reacquires the frozen position; live resume resolves the latest position within the same selected slot. Failed preparation preserves pause. A new pause cancels pending preparation; successful seek or resume starts playback. Volume survives replacement without persistence. Live playback still stops at the selected slot deadline while paused.

## 対話再生の局・番組切替（2026年10月16日）

`--interactive`では`live STATION`で対象局の現在枠へ、`timefree STATION YYYYMMDDHHmmss [--offset SECONDS]`で指定日時を含む枠へ切り替える。入力をEnterで確定したときだけ取得する。未来日時・不正な局ID・開始位置は拒否し、放送状態・契約・配信条件は通常の再生と同じ経路で確認する。

最新要求だけを準備し、認証・取得・デコード・出力機器の準備成功後に旧再生を停止し、旧バッファを破棄する。準備中・失敗時は現在の再生または一時停止を維持する。成功時は新しい番組の指定位置から再生し、音量を引き継ぐ。後続のシークと再開は切替後の放送枠を対象にする。ライブの再開では同じ枠かを確認し、次番組へ自動で移らない。切替完了時は局ID・モード・放送日時を日本時間で表示する。`--seconds`は切替成功後にも再適用する。TUI・チャプター連携は後続実装とする。

## 再生状態の表示（2026年10月16日）

再生開始時と定期通知で、現在の番組名・局ID・モード・放送日時を表示する。番組名は既存のメタデータ取得応答の`title`を使用し、欠落時も再生を妨げず「番組名未取得」とする。端末制御文字を除去し、最大512文字まで保持する。番組名による放送枠の一致判定は行わない。

対話再生の`status`は追加取得を発生させず、現在の状態を通知する。「再生準備中」「再生中」「一時停止中」、音量、出力フレーム／秒数、バッファ不足を表示し、現在の対象と準備中の切替先を区別する。定期通知は5秒ごと、操作と準備結果も次の主ループで通知する。タイムフリーの位置は希望開始位置＋出力済みPCMから求める。ライブの出力秒数を番組内位置と同一視せず、未確認と表示する。放送日時は常にJSTのオフセットを明示する。

## 公式チャプター取得の検証CLI（2026年10月16日）

`chapters STATION YYYYMMDDHHmmss`はログインなしで対象枠のチャプターを取得し、参考位置とタイトルを表示する。既存の番組解決APIで局と指定時刻を照合し、その応答の`eventId`を使う。`episodeIntroductionStartAt`が枠開始と一致する場合だけ取得へ進み、チャプター応答の`stationId`・`programId`も確認する。イベントIDはURLの1要素として安全な文字と長さに制限する。情報欠落・異なる原点では補正を推測せず「対応付け未確認」とする。

メタデータが一致していても音声との対応が検証済みとは扱わず、このCLIは再生へ接続しない。参考値は枠長内でのみ正規化し、楽曲・不正位置を除外した件数を表示する。成功した空配列は「チャプター未提供」、HTTP失敗・JSON不正・対象不一致は失敗として区別する。毎回メタデータと対象チャプターを再取得し、キャッシュ・音声保存・追加の楽曲APIは使用しない。TUIでの取得世代管理とジャンプ再生は後続実装。

## 番組一覧の絞り込みCLI（2026年10月16日）

既存の`programs`の単一局・地域・全国指定へ、`--keyword TEXT`、`--genre ID1,ID2`、`--personality ID1,ID2`を追加する。同じ分類軸の複数IDはOR、番組ジャンル・出演者分類・キーワードはAND。IDは取得データの値と一致させ、分類名の固定表を作らない。`--genre-unclassified`と`--personality-unclassified`で空分類を選べ、同軸のID指定との組み合わせはORになる。

キーワードは番組名・出演者・説明・詳細情報・各タグを対象に、Unicode小文字化後のリテラル部分一致とする。前後空白を除去し、空の条件は拒否する。正規表現・複数語の演算・幅の正規化は行わない。番組ID・番組名による枠の統合はせず、放送前番組や再生可否未確認の扱いも維持する。

取得後の現在データへ純粋なフィルターを適用し、毎回の取得・最大4並列・キャッシュ禁止を維持する。`--classifications`はテキスト一覧の後に今回の取得範囲の分類ID・名称を表示する。JSONは常に絞り込み条件、取得枠数、一致件数、絞り込み前の観測分類を含める。観測一覧を全分類とみなさず、取得失敗の局や地域を推測で補完しない。0件一致でも部分失敗は隠さない。単一局でも不正枠除外があれば`complete=false`・終了コード1とする。期間指定は後述のCLIで対応する。条件保存は後述のCLIに対応し、編集中条件と再生の同時制御は後続実装。

## 期間指定の番組一覧・検索CLI（2026年10月16日）

`programs STATION [START [END]]`、`programs (--areas IDS | --all) [START [END]]`で単日または期間を指定する。日付はYYYYMMDD、開始・終了を含む1〜30放送日とする。終了日省略は単日、日付省略は従来通りJST午前5時区切りの当日だけを取得する。逆転・不正日付・31日以上は取得前に拒否する。メタデータ取得の成功をタイムフリー聴取可能とは扱わない。

地域指定は対象地域の局一覧を期間全体で一度取得して局IDを重複排除し、局と放送日の組み合わせを最大4並列で取得する。単一局の期間取得も同じ上限を使う。全国30日分を暗黙には取得しない。局ID＋開始日時で期間全体の同一枠を重複排除し、開始時刻が異なる分割枠や別局の同名番組は維持する。午前5時をまたいで複数日の応答に現れる枠も切り詰めない。

進捗・失敗には局と放送日を表示し、成功した範囲のみ検索・表示する。未取得日を前回データで補完せず、部分失敗はcomplete=false・終了コード1とする。複数日JSONはdate_rangeと局・日別schedulesを持ち、successful_stationsとsuccessful_schedulesを区別する。requested_schedulesは発見済み対象局の予定取得数で、局発見失敗の未確定分はarea_failuresで通知する。単一局・単日は従来のprograms形式を維持する。条件保存は後述のCLIに対応し、アプリの検索世代・TUI統合は後続実装。

## 検索条件の保存・復元CLI（2026年10月16日）

`searches save NAME <programsの選択・期間・絞り込み>`で通信せず名前付き条件を保存する。同名は更新する。`searches list`、`show NAME`、`delete NAME`で一覧・確認・削除し、`programs --saved NAME`で保存期間も含めて適用し、番組表を新規取得する。名前付き呼び出しに追加の検索条件は混在させず、表示用の`--json`・`--classifications`だけを許可する。

通常の有効な`programs`検索確定時には前回条件を保存する。`programs --restore`は前回の局／地域・分類・キーワードを復元し、保存した開始・終了日を両方ともJST午前5時区切りの当日に戻して取得する。`searches restore`は同じ復元結果を通信なしで確認する。初回・読み込み失敗時は当日・全国・分類／キーワードなしを使用する。TUIは未実装のため、現段階の復元は明示CLI操作で行い、将来の起動処理も同じ日付リセットを使う。画面モード・再生位置は保存しない。

保存先はセッションと同じデータディレクトリの`searches.json`で、`--data-dir`を共用する。バージョン付きJSONに前回条件と名前付き条件のみを原子的に保存し、Unixではディレクトリ0700・ファイル0600とする。番組表や観測分類は保存しない。破損・未対応形式・不正値は理由を表示し、自動で上書きしない。通常検索は保存に失敗しても現在の条件で続行する。名前付き条件の操作は失敗を返す。同時更新は非待機の排他制御で競合を通知し、他の条件を失う書き込みを避ける。条件名は最大64文字、名前付き条件は最大64件とする。
