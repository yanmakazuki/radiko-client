# 機能設計

2026年10月28日時点の仕様です。開発の途中で足した機能は、日付順ではなく「いま何をするか」でまとめてあります。処理の置き場所と容量の上限は [アーキテクチャ](architecture.md)、実機で確認した範囲は [検証範囲](validation.md)、その日の手順と数値は [実装状況](implementation.md) にあります。

取得、認証、再生、保存はライブラリクレート `radiko` が提供します。TUI と CLI はそれを呼びます。画面の操作はこの設計のままです。

仕様を変えるときは、この文書とアーキテクチャを同時に更新します。確認した結果は実装状況へ足し、検証範囲の要約も合わせます。

## 目的

macOS と Linux のターミナルから、全国の番組をジャンル・出演者分類・キーワードで探し、そのまま再生します。

- ライブと、過去30日のタイムフリーを再生する。
- 公式 Web にログインできるダブルプラン契約を前提にする。
- 検索条件を名前付きで保存する。「女性アイドル」は出演者分類である。
- タイムフリーの公式 AI チャプターを表示し、放送枠と時刻が対応している章は、その開始位置から再生する。
- デコードは純 Rust とする。外部プレイヤーや OS のデコーダーへ自動では切り替えない。

録音、音声ファイルの保存、ポッドキャスト、通知、再生位置の保存、macOS と Linux 以外の OS への対応は初期版に入れません。

## 二つの画面

起動時の画面は毎回タイムフリーです。日付は、保存済みの条件があっても当日に戻します。地域・ジャンル・出演者分類・キーワードだけ前回の条件を復元し、初回は全国・分類なし・キーワードなしです。

「当日」は日本時間の午前5時区切りの放送日です。午前0時から5時未満は前日の放送日です。

`v` でライブ一覧を開くと、同じ地域・分類・キーワードのまま当日1日を取り直し、放送中の枠だけを出します。Enter はその枠のライブ再生です。もう一度 `v` を押すと、元のタイムフリーの日付と期間へ戻って取り直します。画面の種類は保存しません。

ライブ一覧で、当日以外の日付を明示して検索すると、指定を捨てずにタイムフリーへ移ります。午前5時を越えて残った古い一覧は、自動では取り直さず、`r` で更新します。開始時刻と終了時刻の境界では、通信せず表示だけを更新します。

画面の上に検索条件、中央に番組一覧と詳細、下に再生状態を置きます。選択中の番組と再生中の番組は、番組名・局・放送日時を別々に示します。一覧を動かすだけでは再生は変わりません。

再生欄は `再生中: [局ID / モード] 番組名` の順です。長い番組名でも局とモードが先頭に残ります。放送日時は次の行で、日本時間のオフセットを付けます。

## キーの意味

| 場所 | キー | すること |
| --- | --- | --- |
| 番組一覧 | Enter | タイムフリー再生。ライブ一覧ではライブ再生 |
| 番組一覧 | `l` | 選択中の、放送中の枠をライブ再生 |
| 番組一覧 | 左右 | タイムフリーを、出力済みの位置から15秒移動 |
| 番組一覧 | `g` | タイムフリーの、枠の冒頭からの整数秒へ移動 |
| 番組一覧 | Space / `s` | 一時停止と再開 / 停止 |
| 番組一覧 | `+` `-` | 音量を5%ずつ変更。0〜100。既定は25% |
| 番組一覧 | `/` | キーワードだけを編集 |
| 番組一覧 | `f` | 日付・地域・分類・キーワードを編集 |
| 番組一覧 | `b` | 名前付き条件の保存・削除・呼び出し |
| 番組一覧 | `c` | 選択中の番組のチャプター |
| 番組一覧 | `r` | いまの条件で番組表を取り直す |
| 番組一覧 | `e` | 今回の取得失敗と不正枠の除外を見る |
| 番組一覧 | `?` | 操作一覧。再生は続ける |
| 番組一覧 | `I` / `O` / `a` | ログイン / ログアウト確認 / セッション再確認 |
| 条件の編集 | Enter | 検索を確定して取得する |
| 条件の編集 | Esc | 編集を捨て、確定済みの条件を残す |
| チャプター | Enter | 対応が取れている章の開始位置から再生 |
| チャプター | Tab | 章一覧と要約のあいだを移る |
| どこでも | `q` または Ctrl+C | 終了。入力欄の `q` は文字 |

入力欄では、再生・取得・認証のキーを操作として渡しません。Ctrl や Alt 付きの文字は入力に足しません。Ctrl+U で欄を消します。`?` や `e` のような普通の文字は入力できます。

## 検索

絞り込みは次の5つです。違う項目のあいだは AND、同じ分類の中の複数選択は OR です。

1. 日付。単日、または両端を含む最大30放送日
2. 地域。全国、複数の地域、または単一の局
3. 番組ジャンル
4. 出演者分類
5. キーワード

入力中の条件と、確定済みの条件は別です。文字を変えたり F2 で選んだりしただけでは通信しません。条件画面の Enter で確定したときに取得します。Esc では確定済みの条件を維持します。

地域は「その地域で聴ける局」です。地域別の局一覧から対象を決め、複数地域に同じ局があれば局 ID で一つにします。放送枠は「局 ID ＋ 開始日時」で一つにします。別の局の同名番組と、開始日時が違う分割枠は残します。番組 ID だけでは枠をまとめません。

全国の局 ID を重複排除し、選んだ期間だけを最大4並列で取得します。起動時に全国30日分をまとめて取ることはありません。番組表・局一覧・分類一覧は保存せず、起動、検索の確定、`r` のたびに必要な分を取ります。取得の失敗を、前の結果で埋めません。

取得の途中、一部の失敗、まだ取っていない範囲は画面に出します。`e` で、今回の地域の失敗、局と放送日の失敗、不正な枠を除外した件数を読めます。新しい検索を確定すると、古い失敗は消します。この画面のキーは通信・認証・再生へ渡しません。

キーワードは、番組名・出演者・説明・詳細・タグへの、大文字小文字を区別しない部分一致です。正規表現や複数語の演算はしません。

分類の ID と名称は、今回の取得結果から集計します。見えている一覧を、存在する全分類とは扱いません。分類が空の番組は捨てず、「未分類」として検索できます。F2 の候補は編集開始時点の観測分だけで、同じ ID の別名は同じ選択です。今回出ていない保存済み ID も残し、外せます。ID の直接入力も使えます。

名前付き条件を明示して呼び出すときは、保存した日付と期間も使います。起動時の自動復元では日付だけ当日に戻します。`b` の保存・削除・呼び出しだけでは取得も再生も変わりません。呼び出しは編集画面へ渡し、そこでの Enter で検索します。

最後に確定した条件は、正常終了のときに保存します。名前付き条件の書き込みが終わったか確認できない終了では、前回条件の保存を省略します。

番組一覧は、画面に出る行だけを整形します。選択位置は一覧全体で持ちます。PageUp と PageDown は、直前の描画で決まった行数だけ動きます。

## 放送状態と再生可否

当日の放送前の番組も出します。日本時間の現在と、開始・終了から「放送前」「放送中」「放送終了」を出し、時刻が経てば通信せず更新します。

放送前の再生操作は、理由を出して配信を取りません。いまの再生も止めません。放送が終わったことだけでは、再生可能とは判断しません。

再生可否は放送状態と別に示します。

- まだ確認していないときは「再生可否未確認」
- 放送前、終了した枠のライブ、契約や配信条件で再生できないときは、その理由
- いま再生している枠とモードが一致し、出力へ渡したフレームがあるときだけ「現在の再生で配信確認済み」

停止したあと、別の枠、別のモード、準備だけの状態は未確認に戻します。確認済みの表示を、次の再生で権限確認を省く理由にはしません。再生のたびにセッションと、その番組の配信条件を確認します。

## 再生

一覧の Enter はタイムフリー、ライブ一覧の Enter と `l` はライブです。`l` は放送前と終了済みを、通信する前に拒否します。

準備が終わるまではいまの音声を続けます。準備が成功してから切り替え、失敗したら今の再生を維持します。新しい要求は、古い準備だけを取り消します。切り替えが確定したあとに新しい出力が失敗したら、理由を出して止まり、前の番組へは戻りません。

一時停止は、出力済みの位置を保持します。再開するとき、タイムフリーはその位置、ライブは同じ枠の最新位置を取り直します。一時停止のあいだも、ライブは選んだ枠の終了日時で止まります。音量 0 は無音にしますが、位置は進みます。音量はファイルに残しません。変更を再生側が受け取れなかったときは、画面の設定値も変えません。

シークはタイムフリーだけです。ライブと、枠の外は拒否します。`g` は枠の冒頭からの整数秒、左右は出力へ渡した位置からの15秒です。入力を始めたときの局 ID と開始日時を要求に付け、実行時の対象が違えば準備を始めません。時刻を確認できない配信は、推測して移動しません。

チャプターの Enter は、同じ枠のタイムフリーならシーク、別の枠やライブからなら、指定位置のタイムフリーへ切り替えます。

番組の終わりでは止まり、次の番組へは進みません。ライブは選択した枠の終了日時で止め、残ったバッファを捨てます。タイムフリーは選択した枠の末尾で止めます。画面には「番組終了」と出します。

再生中に、出力の確認そのものが1秒より長く空いたときは、プロセスが止まっていたとみなしてすぐには止めません。基準を戻してもう一度待ち、コールバックが動けば続けます。それでも動かなければ出力を作り直します。確認が空いていないのにコールバックが3秒進まないときは、これまでどおり出力を止めます。ライブで30秒を超えて新しいセグメントが来ないときは、無音のままプレイリストを取り直します。待ちは1秒から倍々で伸ばし、10秒で頭打ちにします。再生が始まったあとのライブで、そのプレイリスト更新が HTTP 404、または認証切れの 401/403 のときは、その場で止めません。保存してある最初の配信 URL から、マスタープレイリストがあればそれも含めて引き直し、必要なら認証も更新します。引き直した一覧は、これまでと同じ追いつきと巻き戻り判定に渡します。通し番号の系列が変わったときはリセットです。404 が続くときも再接続の 5 分まで試し、超えたら上限の文言で止めます。終了リストが返ったとき、認証そのものが拒否されたとき、局が最初から見つからないときは、そこでは止めます。タイムフリーも同じ途絶では先へ飛ばさず、戻ったら続きから再生します。窓から外れていれば「通信が長く途切れたため、続きを再生できなくなりました。番組を選び直してください」で止めます。これはプレイリストの形式エラーではありません。再接続に使う時間の上限は5分です。止まった時間そのものは数えません。5分は、60〜90秒の通信断に HTTP のタイムアウトと再試行が重なっても収まり、戻らない機器や配信を無音のまま残さない長さです。上限を過ぎたときと、出力の作り直しに失敗したときは「再接続の上限を超えたため再生を停止しました。番組を選び直して再生してください」で止めます。再接続中の画面は「再接続中…（N秒）」です。そのあいだも終了、停止、音量は受け付けます。開始前に最初の音声が30秒来ないときは、これまでどおり止めます。自動で別の機器へは切り替えません。

出力機器は、その時点の CPAL 既定出力と同じ名前の列挙デバイスを開きます。同じ名前がなければ CPAL の default を使います。切れたあとの自動再開、機器の一覧からの選択はしません。形式は、PCM と同じレートの mono または stereo の f32、i16、i32 です。f32 を優先し、なければ i32、その次に i16 を選びます。整数形式は音声コールバックで f32 から変換します。レートが範囲に入らなければ、このプロセスでは変換せず、必要なレートと機器の対応範囲をエラーに出します。OS のデコーダーへは切り替えません。

macOS のホストは CoreAudio です。列挙デバイスを開いているあいだ、OS の既定出力が変わってもそのストリームは追従しません。

Linux のホストは ALSA です。CPAL 0.16.0 は既定の名前を `default` とするので、開けるときはその PCM を開きます。`pipewire`、`pulse`、`jack`、`oss`、カード名の `plughw` は、名前が既定と違うため開きません。JACK 機能は使いません。ALSA ライブラリの診断は、通常は端末へ出しません。失敗は日本語のエラーとして出します。機器が無いときは「既定の音声出力機器がありません」です。生の診断が要るときは、起動前に環境変数 `RADIKO_ALSA_LOG=1` を付けます。デスクトップの既定機器への追従と、ALSA プラグインの中の変換は、このプロセスの外です。Linux の実機再生は未確認です。ビルドには pkg-config と libasound の開発ファイルが要ります。

`output-info` は対応の宣言を読むだけで、再生の成功や、再生中の出力先の追跡ではありません。

## チャプター

公式 AI チャプターのタイトルと開始位置を出し、条件を満たす章はタイムフリーのその位置から再生します。独自の文字起こしや AI 生成はしません。楽曲用の別 API も足さず、`isMusic=true` は除外します。

取得は、番組情報の `eventId` を使った次の URL です。公開実装と、このプロジェクトでの取得を根拠にしています。公式が保証した外部向け API 仕様としては扱いません。番組表 XML の番組 ID と `eventId` は別の値として保持します。

```text
GET https://api.annex-cf.radiko.jp/v1/programs/{eventId}/chapters
```

参照しているフィールドは `chapters`、`titleLong`（`title` より優先）、`fromSec`、`toSec`、`summaryLong`、`isMusic` です。

`c` を押した番組の分だけ取得します。全国分の一括取得や永続化はしません。開き直しと `r` では取り直します。取得中も失敗しても、いまの再生は続けます。古い応答を別の番組へは出しません。

表示は次を区別します。

- 取得中
- チャプター未提供。成功した空配列は、生成待ちの可能性もあるのでこう出します
- 取得失敗。再取得できます
- 番組との対応付け未確認。イベント情報を確認できない、開始位置が枠と違う、放送枠の照合が一致しない、に分けます

開始が負、数値でない、枠の末尾以降、終了が開始以下、枠の外、という項目はジャンプ対象にしません。不正な件数を出し、有効な項目を開始位置順に扱います。タイトルは空白を除いて `titleLong`、`title` の順で、両方空なら「無題」です。

ジャンプできるのは、局・`eventId`・放送枠を照合し、イベントの音声原点が枠の開始と一致する章だけです。原点が違う枠の補正はしません。実例が現れ、音声との関係を確認できるまで追加しません。チャプターがあることだけでは再生可能と判断せず、通常の権限確認とシークを通します。再生できなければ理由を出し、今の再生を続けます。

再生中の番組と、見ている番組の局・開始・終了・タイムフリーが一致するときだけ、今の章を強調します。強調は開始以上・終了未満です。隙間では強調しません。重なるときは開始が最も遅い項目、同じ開始なら元の配列で先の項目です。選択カーソルは、強調とは別に動きます。要約は先頭1200文字までで、上限を画面に出します。

`chapters` CLI は一覧だけで、再生へは繋ぎません。

## 認証と保存

ログインは専用の操作です。パスワードはマスクし、コード、設定、ログ、テストデータに残しません。永続化するのは再利用できるセッションだけで、バージョン付き JSON の平文です。Keychain、暗号化、保存用のパスフレーズは使いません。

既定の保存先は、`directories` で得るユーザーデータディレクトリの `session.json` です。`--data-dir` でディレクトリを指定できます。起動時に読み、有効性を確認します。セッションの保存は、番組データを保存しないルールとは別です。

ファイルがなければ未ログインで起動し、その確認では認証の通信をしません。読み込み失敗、破損、未対応の形式、権限の異常では理由を出し、ファイルを上書きせず、未ログインのまま番組を探せます。明示的なログインが成功したときだけ、新しいセッションを保存します。失敗したログインでは既存ファイルを残します。

保存は一時ファイルからの原子的な置換です。一時ファイルを含め、Unix ではディレクトリ `0700`、ファイル `0600` です。ログアウトはメモリと `session.json` からセッションを消します。検索条件は消しません。

TUI の `I` は、送信するまで通信しません。パスワードは画面に出さず、メモリ上ではゼロ化できる文字列で持ちます。`O` は `y` で確定し、再生を止めてからセッションファイルを消します。ログインとログアウトの実行中は、別の認証更新を受け付けません。画面を閉じても、すでに受理したログインと削除は中断しません。終了時に結果を確認できないときは、端末を戻したあとに保存状態の確認を案内します。

セッションが失効したら再ログインを案内します。通信失敗は失効と断定しません。ログインの成功、契約、その番組の配信条件、サーバーの応答は別々に見ます。エリアフリーと30日聴取のフラグは、有効・未加入・未確認を分けて出します。この表示は最後の確認結果であり、個々の番組の再生許可ではありません。

検索条件は同じデータディレクトリの `searches.json` です。前回条件と名前付き条件だけを保存し、番組表や観測した分類は入れません。壊れたファイルは自動で上書きしません。通常の検索は、条件の保存に失敗しても続行します。名前付き条件の操作は失敗を返します。同時の更新は、待たない排他で競合を通知します。条件名は最大64文字、名前付き条件は最大64件です。

Cookie、認証トークン、署名付きの配信 URL、パスワードは、ログにも検証資料にも出しません。

通信断の再試行は、一回の取得につき最大3回です。認証の拒否、404、429、取り消し、サイズ超過は、HTTP 層では再試行しません。ログインの POST は一度だけ送り、自動では再試行しません。再生が始まってからの通信断は、これとは別に、5分までプレイリストを取り直します。

再生中に限って、プレイリスト、初期化情報、音声セグメントの HTTP 401 は配信認証を1回やり直してから、その要求を1回取り直します。再認証が失敗したときと、取り直しも 401 のときは「認証期限切れ」と表示して停止します。成功した再認証から20秒以内の次の 401 は、新しい認証を呼ばずに持っているトークンで1回だけ取り直します。403 と 429 はこのやり直しをしません。429 はアクセス制限のままです。取り消しは期限切れと別の文言です。再認証できたときは、TUI の認証行に「配信認証を更新して継続」を足し、再生通知に「配信認証を更新して再生を続けます」を出します。止まったときは認証行に「再生側で認証失敗 / a 再確認」を足します。通信診断に足すのは完了した回数だけで、トークンは出しません。

## 音声

HLS を更新しながら通し番号で受け取り、同じデコーダーと出力ストリームで続けます。音声は保存しません。

ライブで、取得済みの通し番号より先に窓が進み、次のセグメントがもう無いときは、再生を止めません。再開位置は、終端から target duration の3倍以内に始まる最も古いセグメントです。短い窓ではプレイリストの先頭、それより長い窓ではライブ端の近くです。先頭から再開した通知は「配信窓の先頭から再開しました（累計N）」、ライブ端の近くから再開した通知は「ライブ端に追いつきました（飛ばしたセグメントは累計N）」です。

`MEDIA-SEQUENCE` が少し古いだけの応答は、何も再生せず、デコーダーも巻き戻り回数も変えず、次の取得を待ちます。無視するのは、新しい窓の末尾が最後に再生した番号からそのプレイリストのセグメント数以内だけ前にあるときと、窓がその番号をまたぐときです。1セグメントの窓では 12 の次に届いた 11 を無視し、10 はリセットです。6セグメントで 12〜17 を再生したあとの 11〜16 も無視します。それより前の末尾と、大きく小さい番号から始まる配信の切り替わりはリセットです。次の番号との差が、そのプレイリストのセグメント数より大きい飛びもリセットです。その差は飛ばした数に足しません。差がセグメント数以下の取りこぼしだけを足します。リセットで捨てた古い番号は足しません。タイムフリーの欠落と巻き戻りは失敗のままです。通信が途切れているあいだも、タイムフリーは先のセグメントへ飛ばしません。再認証、終了時に出力を先に閉じること、サンプル形式の選択は変えません。

対応する連続再生は次です。

- ADTS の AAC。SBR を含む HE-AAC は、実データの SBR を検出してから成功にします。宣言だけを成功にはしません。
- 初期化情報付きの、単一 AAC トラックの fragmented MP4。バイト範囲の指定はないものに限ります。時刻、長さ、データ範囲を照合し、初期化情報の内容が変わったときは明示的な不連続を要求します。

暗号化、バイト範囲指定、複数トラック、複数 run、編集リストには対応しません。CRC 付きの ADTS、複数 raw block、PCE によるチャンネル構成は拒否します。

2026年10月24日までに確認した実配信の先頭は、MPEG-2 AAC の ADTS で、宣言は `mp4a.40.5` でした。fragmented MP4 の連続再生は、生成した音声と、ADTS をメモリ上で詰め直した照合までです。実配信で非 ADTS が見つかるまでは、上の未対応を足しません。

PS は、AudioSpecificConfig の `ps` が真で、復号に成功したときだけ「明示あり」と出します。ADTS の公開 API からはビットストリーム上の PS を読まないため、ADTS は明示なしのままです。`mp4a.40.29` の宣言やステレオへの拡張だけでは、PS が成立したことにはしません。

シークできるのは、HLS の `PROGRAM-DATE-TIME` で位置を確認できる配信だけです。表示する位置は、その時刻と、出力コールバックへ渡したフレーム数からです。耳に届いた時刻や、機器の遅延は別です。ライブの出力秒数は、番組の中の位置としては出しません。

バッファには上限があります。デコード済み PCM の待ちは2セグメント、1つあたり最大4MiB です。機器側のリングは2秒です。待ちを満たすために再生開始を遅らせません。局の切り替えとシークでは、古い音声を新しい再生へ混ぜません。

通信とデコードは、音声コールバックの外で行います。コールバックが足りないときは無音を出しますが、その無音の分は再生位置を進めません。

## 診断に出るもの

再生欄の「今回の出力」は、今の出力世代の秒数、不足したフレームとその秒数、PCM の形式、セグメント数です。シークや切り替えでゼロに戻り、聴いた時間の累計ではありません。正常に止めたときは最後の値を残します。エラーで最終の集計がないときは「終了時未集計」と出します。これは停止後に全部を集計し直した値ではありません。

「処理診断」は、取得、復号、PCM の配送待ち、配信の更新待ちの実時間です。CPU 時間ではありません。配送待ちと更新待ちは、取得や復号の最大値に混ぜません。再生ワーカーが替わると値も替わります。

「待機 PCM」は、主制御がまだ受け取っていないキューと配送待ちで、最大3個です。再生側が持っている PCM と、機器のリングは含みません。0個であることを、音が残っていないことにはしません。

「通信診断」は、応答待ち、本文の受信、再試行待ちです。応答待ちには名前解決、接続、TLS が含まれ、サーバーが応答を遅らせた時間だけではありません。HTTP の番号は、今または直前の試行で受け取った値です。次の試行が始まると「未取得」に戻します。本文の途中で失敗しても 200 は残るので、200 だけでは成功にしません。通信失敗の件数、そのうちの期限超過と接続失敗は別々の数で、足し合わせません。ライブの窓へ追いついたときは、飛ばしたセグメントの累計を「飛ばしたセグメント」として足します。通し番号をリセットした回数も、1回以上のときだけ「通し番号の巻き戻り」として足します。どちらも 0 のときは出しません。CLI の状態表示は、同じ通信診断の行です。TUI の再生通知は、飛ばした数か巻き戻り回数が増えたとき、先頭からなら「配信窓の先頭から再開しました（累計N）」、ライブ端からなら「ライブ端に追いつきました（飛ばしたセグメントは累計N）」と出します。配信認証の更新、再生停止、認証期限切れの通知が出ているときは、その文を置き換えません。トークンや URL は出しません。

高さ36行未満の端末では、`?` の操作一覧から診断を読みます。行は折り返します。

## オフラインの起動確認

`tui --offline` はテストと CI 専用である。ヘルプには出さない。利用者向けの起動オプションではない。番組表は通信せず、メモリ上の試験データです。どの地域の局一覧を聞かれても試験局 TBS を一つ返し、指定した局と放送日には「オフライン番組」（6:00〜7:00、日本時間）を一つ返します。ログイン、セッションの通信確認、チャプター取得、再生、音声機器は開きません。`session.json` と検索条件のファイルは、`--data-dir` でも既定の保存先でも、読まない、書かない、消さない。ログアウト（`O` のあと `y`）は何もしません。この番組表と表示は、実配信の取得結果や再生可否ではありません。

## 終了

終了とエラーでは、音声を止めてから、raw mode と代替画面を解除して端末を戻します。SIGINT、SIGTERM、SIGHUP は同じ終了処理へ入ります。SIGKILL では復元も、受理済みの保存の完了も保証しません。

受理済みのログイン、ログアウト、名前付き条件の書き込みは、画面を閉じても中断しません。終了時は最大200ms だけ結果を待ち、確認できなければ端末を戻したあとに案内します。音声出力を閉じたことは最大1秒待ちます。その待ちは実行中の HTTP を含めません。1秒を超えても端末は戻します。実行中の HTTP が終わるまで、端末の復元を待ちません。

## 完成と確認の分け方

完成条件は、実配信を30分連続で再生しながら、検索とキー操作が応答することです。

自動テストはアカウントと radiko に依存させず、fixture とモックと生成した音声で、境界、壊れた応答、権限、失敗を見ます。実通信と実機の音声は明示的に実行し、日付、対象、手順、結果を実装状況へ残します。取得できたこと、先頭をデコードできたこと、コールバックへ渡したフレーム数は、それぞれ連続再生や聴こえたことの確認とは別です。

守る確認は次です。

- 空の分類、未知の分類、同じ番組 ID の分割枠、午前0時から5時の放送を落とさない。
- 分類の AND と OR、条件の保存と復元、全国取得の一部失敗を区別する。
- 複数地域の同じ局と枠は一つになり、別局の同名番組と分割枠は残る。
- 起動、確定、手動更新で取り直し、失敗を前回のデータで埋めない。
- 入力、選択、編集の取消では通信せず、確定で取得する。検索の失敗中も再生が続く。
- 放送前の再生操作で配信を取らず、今の再生も止めない。未確認を再生可能と出さない。
- 午前4時59分の起動は前日の放送日、午前5時は当日。保存した日付は当日に戻り、他の条件は残る。
- ライブは終了日時、タイムフリーは枠の末尾で止まり、次の番組の音は出ない。
- ログイン失敗、失効、契約不足、配信対象外を区別する。
- セッションのなし、破損、未対応形式、失効、保存の中断、権限、ログアウト、`--data-dir` を確認する。
- セグメントの境、形式の変化、バッファ不足、シーク、局の切り替え、機器の切断、終了を確認する。
- テスト専用の `tui --offline` を疑似端末で起動し、画面を切り替えて `q` で終了する。ヘルプには出さない。終了コード 0、端末の復元、出力に `ALSA lib` とパニックがないこと。radiko へは接続しない。
- チャプターの空配列、不正な時刻、タイトルの優先、取得失敗、古い応答の破棄を確認する。閲覧だけでは再生が変わらず、同じ枠はシーク、別の枠は切り替えになる。
- チャプターの実通信では、`eventId` と枠の対応、認証の要否、7日以内と8〜30日前、開始秒数と実際の音の位置を分けて記録する。

環境や契約で実行していない確認は、実行したものと分けて書きます。
