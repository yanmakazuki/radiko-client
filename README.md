# radiko-client

macOS向けRust製radiko TUIクライアントです。全国・地域・局を対象に、最大30放送日の番組を分類・キーワードで検索し、条件を保存できます。TUIとCLIから会員ログイン、ライブ／タイムフリー再生、一時停止・再開・シーク・音量操作を行えます。公式AIチャプターは閲覧でき、放送枠との時刻対応を確認できた場合にジャンプできます。純RustのAAC/SBRデコードとCPAL出力を使用します。確認済みの対象と残る制約は[検証一覧](docs/validation.md)、日付・ビルドごとの結果は[実装状況](docs/implementation.md)を参照してください。

局・放送日を指定して番組一覧を取得できます。ログイン不要で、実行ごとに再取得します。

```sh
cargo run -- programs TBS
cargo run -- programs OBS 20261015
cargo run -- programs TBS 20261015 --json
cargo run -- programs --areas JP13,JP14 20261015
cargo run -- programs --all 20261015 --json
```

日付省略時は日本時間の午前5時を境界とする当日の放送日です。番組名・出演者・番組ジャンル・出演者分類と、取得時点の放送状態を表示します。翌日未明と放送前の番組も含みます。再生可否は未確認として扱います。JSONには説明・タグも含みます。`--areas`はその地域で聴ける局の一覧をもとに選択します（JP1〜JP47、カンマ区切り）。`--all`は47地域を取得します。地域間で共有する局を重複排除し、指定した1日分を最大4並列で取得します。テキスト表示は取得できた局から順次表示し、JSONは最後にまとめて出力します。進捗は標準エラーに出力します。

地域・局の取得失敗や不正枠除外がある場合は、取得できた結果と欠落範囲を表示し、終了コード1を返します。JSONの`complete`も`false`になります。失敗した地域の対象局数は未確定です。同じコマンドを再実行すると全件を再取得します。単日・期間の分類／キーワード検索と条件保存に対応しています。閲覧TUIでは放送状態を時刻から更新し、番組表の再取得は手動で行います。

```sh
cargo run -- login
cargo run -- session
cargo run -- logout
```

`login`は対話端末でメールアドレスとパスワードを入力します。パスワードは非表示で、保存しません。ログイン後にセッションの有効性を別途確認し、エリアフリー・タイムフリー30の契約情報を表示します。契約情報だけで個別番組が再生可能とは判断しません。

保存するのは再利用可能なセッションのみです。保存先は`directories`のユーザーデータディレクトリ内の`session.json`です。`--data-dir DIR`で変更できます（例：`cargo run -- --data-dir ./local-data login`）。専用ディレクトリを指定してください。Unixではディレクトリ0700・ファイル0600が必要で、新規作成時に設定します。セッションは平文のため、Gitなどで共有しないでください。

`session`は保存済みセッションを自動で読み込み、サーバーで確認します。ファイルがない場合は未ログイン、破損・未対応形式なら理由を表示して元ファイルを保持します。`logout`は通信せずローカルのセッションを削除します（公式Webなど別端末のログインは変更しません）。明示的な`login`が成功したときだけ保存を置き換えます。

連続再生は次のコマンドで行います。既定では選択した番組枠の末尾で停止し、次の番組へは移りません。日時は日本時間です。

```sh
cargo run -- play-live OBS
cargo run -- play-live TBS --seconds 30
cargo run -- play-timefree TBS 20261015120000 --seconds 30
cargo run -- play-timefree TBS 20261006120000 --seconds 30
```

`--seconds N`（1〜86400）は出力するメディア時間の上限です。省略時は番組末尾まで再生し、ライブは終了日時も上限にします。`Ctrl+C`で停止できます。保存済みセッションと個別番組の配信条件を確認してから取得します。タイムフリーは指定時刻を含む放送枠の冒頭から再生し、`--offset SECONDS`で開始位置を変えられます。

HLSを更新しながら通し番号順に取得し、同じデコーダーと出力ストリームを維持します。音声を保存せず、PCMの待機キューは2セグメント（各最大4MiB）、出力リングは2秒分に制限します。欠落・形式変更・機器エラー・更新停止は理由を表示して停止します。HTTPやデコードは音声コールバックから実行しません。Ctrl+Cで音声を止め、HTTPのヘッダー待ち・本文受信とパケット境界でのデコードを取り消します。OSのDNS処理と単一AACパケットの呼出し自体は中断しません。準備中の通信にもタイムアウト／再試行上限が適用されます。

対応形式はADTS/AAC、mono/stereo・f32・PCMと同じレートの出力機器に限ります。長時間出力や聴感・機器操作の結果は対象とビルドによって異なります。[検証一覧](docs/validation.md)で成功例と未解決の停止を確認してください。

タイムフリーの開始位置指定と再生中のシークにも対応しています。

```sh
cargo run -- play-timefree TBS 20261015120000 --offset 60 --seconds 10
cargo run -- play-timefree TBS 20261006120000 --interactive
```

`--interactive`では次を入力し、Enterで確定します。

- `seek 120`：番組冒頭から120秒の位置へ移動（小数も指定可能）
- `+15`／`-15`：出力済みPCMの位置から15秒進む／戻る
- `q`：停止して終了

シーク先の認証・配信条件と時刻を確認し、2秒分（末尾付近は残り分）のPCMと音声出力機器を準備してから切り替えます。準備中・失敗時は元の音声を継続し、連続した操作では最新の要求だけを反映します。ライブ・放送枠外のシークは拒否します。`--seconds`の上限はシーク成功後に改めて適用します。シーク先の準備前に現在の再生が終了した場合は、そのまま終了します。

対応はHLSの`PROGRAM-DATE-TIME`で位置を確認できる配信に限ります。確認できなければ推測せず切替を拒否します。表示位置はHLS時刻と出力コールバックへ渡したフレーム数に基づきます。聴感照合は一部の章だけで、全体の同期精度は未検証です。TUIでは左右で15秒シークし、一覧のEnterで別枠へ切り替えられます。

音声出力の検証も明示的なコマンドで実行します。生成音と`play-sample`は既定の出力機器から音が出ます。

```sh
cargo run -- probe-output 1                     # 1秒の小さい440Hz生成音（1〜10秒、省略時2秒）
cargo run -- probe-output --mute 180            # 通信・復号なしの無音連続出力（1〜1800秒、省略時30秒）
cargo run -- play-sample OBS                    # 地元ライブの先頭1セグメント
cargo run -- play-sample TBS                    # エリア外ライブ（契約が必要）
cargo run -- play-sample TBS 20261014120000     # 指定枠のタイムフリー冒頭1セグメント
```

`probe-output --mute`は音源も音量もゼロで、通信・認証・デコードを使わず出力機器だけを確認します。1秒PCMと2秒リングを繰り返し使い、5秒ごとにフレーム数・不足を報告します。Ctrl+Cで中断でき、出力ループにも指定秒数＋30秒の実時間上限を設けています。スリープ復帰や出力先変更でコールバックが止まった場合は理由を表示して終了するため、出力先を確認して明示的に再実行してください。成功しても配信・デコード・聴感の確認にはなりません。

`play-sample`は保存済みセッションを確認し、既存の放送枠・契約・地域・配信条件の判定を通してから取得します。`--data-dir DIR`も使えます。ADTS/AACのみが出力対象で、PCMを最大4MiBまで検証してから、2秒分のバッファを介してCPALへ送ります。出力ゲインは0.25固定、mono/stereo・f32・PCMと同じレートに対応する機器を使用し、形式が合わなければ理由を表示します。OSの音声デコーダーや外部プレイヤーは使いません。

先頭約5秒などの**1セグメントだけ**を出力して停止します。ライブでは選択枠の残り時間も上限にします。表示するフレーム数は音声コールバックへ渡した数で、耳に届いたことや音質を保証する指標ではありません。末尾は250ms待って出力ストリームを解放します。大きな機器遅延での末尾、実機の切断や放送終了境界は未検証です。連続再生は上記の専用コマンドを使用してください。タイムフリーのシークと局・番組切替は、連続再生コマンドの`--interactive`で利用できます。

配信取得の検証は明示的に実行します。保存済みセッションを使い、放送枠・契約・地域・番組の配信条件を確認してからHLSと先頭の1セグメントを取得します。

```sh
cargo run -- probe-live TBS
cargo run -- probe-timefree TBS 20261014120000
cargo run -- probe-timefree TBS 20261005120000
```

日時は日本時間の実日付による`YYYYMMDDHHmmss`で、時は00〜23を指定します。指定時刻を含む放送枠全体を解決し、その冒頭のサンプルを確認します。過去の日付は実行時の聴取期限に合わせて選び直してください。`--data-dir DIR`も指定できます。

結果には放送枠、認証エリア、HLS宣言コーデック、サンプル形式、デコード確認の成否を表示します。Cookie・トークン・配信URL・音声データは出力／保存しません。終了コード0はHLSとサンプルの取得成功を表し、デコード成功や連続再生の保証ではありません。

2026年10月15日にOBSの地元ライブ、TBSのエリア外ライブ・前日分・10日前のタイムフリーで、先頭約5秒の全パケットを純RustでPCMへ変換できました。ADTSは`rusty_aac 1.1.0`、その他のサンプル形式はSymphoniaを使用します。結果には入力のコアレート、PCMのレート・チャンネル数、SBR検出、パケット数、処理時間も表示します。確認した実音声はコア24kHzから48kHz・ステレオへのSBR再構成を通っています。

`probe-live`／`probe-timefree`は音声出力を行わず、PCMは1パケットごとに破棄します。2026年10月16日に`probe-output`と`play-sample`で短い音声を実機の出力経路へ渡せました。PSの明示シグナルと聴感品質、連続再生・番組末尾の停止は未検証です。CRC付き／複数raw blockのADTS、PCEによるチャンネル構成、非ADTSのHE-AACは今回の接続範囲外として拒否します。

```sh
cargo run -- --help
cargo run -- inspect-chapters tests/fixtures/chapters.json 90 0
```

引数はJSONファイル、選択した放送枠の秒数、イベント音声原点から放送枠開始への補正秒数です。合成fixtureでは補正を0としています。実番組の原点対応を確認する機能はまだなく、この操作で聴取可否やシークの正しさは検証できません。

```sh
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
```

この環境では既定のMacOSX27.0 SDKでリンクに失敗します。必要に応じて各Cargoコマンドに`SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk`を付けて実行してください。

[機能設計](docs/design.md) / [アーキテクチャ](docs/architecture.md) / [実装状況と検証の制約](docs/implementation.md)

Interactive playback also accepts `pause`, `resume`, and `volume 10` (Enter to confirm; default volume 25%, range 0..100). Volume zero mutes while playback advances. Timefree resumes from the paused position; live resumes at the latest position within the same program. `play-live` also accepts `--interactive`. Live playback stops at the selected program end even while paused.

対話再生中の局・番組切替（Enterで確定）：

```text
live OBS
timefree TBS 20261015120000
timefree TBS 20261006120000 --offset 120
```

切替先の準備中・失敗時も現在の再生を維持します。成功後に音量を引き継いで切り替え、以後のシーク・再開も新しい番組を対象にします。`--seconds`の上限は切替後に再適用します。

対話再生中の`status`で現在の番組名・局・放送日時（`+09:00`）・状態・音量・準備中の切替先を表示します。通信や再生切替は追加で行いません。同じ情報を5秒ごと、および操作・準備結果の反映時にも表示します。ライブは出力秒数を示し、未確認の番組内位置を再生位置として表示しません。番組名が取得できない場合は「番組名未取得」と表示します。

公式AIチャプターの取得・一覧確認（ログイン不要、日時は日本時間）：

```sh
cargo run -- chapters TBS 20261015120000
cargo run -- chapters TBS 20261006120000
```

毎回メタデータと対象チャプターを取得し、楽曲と不正位置を除外します。枠との対応が不明なら位置補正を推測しません。このCLIは一覧表示のみを行い、原点を照合できた枠のジャンプ再生はTUIで操作します。TBSの前日枠で13件、10日前枠で14件の一覧取得を確認しました（2026年10月16日）。

番組一覧の絞り込み（毎回取得、単一局・地域・全国で利用可能）：

```sh
cargo run -- programs TBS 20261015 --keyword 生活
cargo run -- programs TBS 20261015 --classifications
cargo run -- programs TBS 20261015 --genre P003,P007 --personality C015 --keyword 生活 --json
cargo run -- programs --areas JP44 20261015 --genre-unclassified
```

分類IDは`--classifications`またはJSONの`observed_classifications`で確認できます。同じ分類内のIDはOR、ジャンル・出演者分類・キーワードはANDです。未分類は`--genre-unclassified`／`--personality-unclassified`で選択できます。キーワードは番組名・出演者・説明・詳細情報・タグの大小文字を区別しない部分一致です。

JSONの`source_program_count`は絞り込み前、`matched_program_count`は一致した件数です。観測分類も絞り込み前の今回の取得範囲から集計し、全分類とは扱いません。取得欠落や不正枠は検索結果が0件でも不完全として通知します。TUIでは`f`で地域・期間・分類・キーワードを編集して検索でき、起動引数でも指定できます。

期間を指定する場合は開始日の後に終了日を指定します（YYYYMMDD、両端を含む最大30放送日）。

```sh
cargo run -- programs TBS 20261014 20261015 --keyword 生活 --json
cargo run -- programs --areas JP44 20261014 20261015 --keyword 生活 --json
```

局一覧は期間全体で一度取得し、番組表は局×日を通じて最大4並列で取得します。JSONでは`date_range`、`successful_stations`（局数）、`successful_schedules`（局・日数）を区別します。部分失敗は局と放送日を表示し、取得できた分だけを返して終了コード1とします。日付省略は従来通り当日のみで、暗黙の30日一括取得は行いません。

検索条件の保存・呼び出し（保存・一覧・確認・削除は通信しません）：

```sh
cargo run -- searches save 生活 TBS 20261014 20261015 --keyword 生活
cargo run -- searches list
cargo run -- searches show 生活
cargo run -- programs --saved 生活 --json
cargo run -- searches delete 生活
```

通常の検索条件も前回分として保存します。`programs --restore`は日付を当日1日に戻して前回条件で再取得し、`searches restore`は復元結果を通信せず表示します。名前付き条件では保存した期間を適用します。混在する検索オプションは受け付けません。

保存先はセッションと同じデータディレクトリの`searches.json`です。`--data-dir DIR`で変更でき、セッション情報・番組表・音声は条件ファイルに含めません。破損ファイルは自動で上書きせず、保存失敗でも通常検索は続行します。TUIは引数なしで起動すると、前回条件を当日1日に戻して復元します。

## 検索・ライブ／タイムフリー再生TUI

番組の閲覧はログイン不要です。引数は`programs`と同じ局・地域・期間・絞り込みを使用できます。

```sh
cargo run -- tui
cargo run -- tui --areas JP44
cargo run -- tui TBS 20261015
```

引数なしでは前回の地域・分類・キーワードを復元し、日付だけをJST午前5時区切りの当日1日に戻します。初回は当日・全国・分類／キーワードなし、初期画面は毎回タイムフリーです。

| 操作 | キー |
| --- | --- |
| 操作一覧を開く／閉じる | `?`（一覧ではEsc・qでも閉じる） |
| 取得状況・未取得範囲 | `e`で地域／局・日の失敗と不正枠除外の対象を開き、上下・ページ・Home/Endで閲覧。`e/Esc/q`で戻る |
| 番組選択／詳細閲覧 | 上下・`j/k`、`PageUp/PageDown`で1画面、`Home/End`で先頭／末尾 |
| タイムフリー／ライブ一覧切替 | `v`（切替ごとに新規取得） |
| 選択番組を再生 | `Enter`（ライブ画面ではライブ、それ以外はタイムフリー） |
| 選択した放送中番組をライブ再生 | `l` |
| 一時停止／再開・停止 | `Space`・`s` |
| 15秒シーク・整数秒の位置入力 | 左右・`g`（タイムフリーのみ） |
| 音量を5%ずつ変更 | `+`／`-`（再生前も操作可能） |
| キーワード／全条件編集 | `/`・`f` |
| 名前付き検索条件 | `b` |
| 番組表の再取得・チャプター閲覧 | `r`・`c` |
| ログイン・ログアウト確認・セッション再確認 | `I`・`O`・`a` |
| 終了 | `q`・Ctrl+C（入力画面ではqは文字入力） |

ライブ一覧は当日分の取得結果から放送中だけを表示し、開始／終了境界では通信なしで行を更新します。選択移動や画面切替だけでは再生を変更しません。`v`で元のタイムフリー条件・日付／期間に戻って再取得します。ライブ画面から当日以外の日付を明示して検索するとタイムフリーへ移ります。午前5時を越えた旧日付の一覧は`r`で更新してください。

再生欄は`[局ID / モード]`を先頭に置き、その後に番組名を表示します。長い名前でも再生対象を識別でき、通常画面の次行で放送日時を確認できます。

詳細の放送状態と配信確認は別表示です。現在の再生と同じ枠・モードで出力済みの場合だけ配信確認済みとし、停止後は未確認へ戻ります。再生操作ではその都度セッションと配信条件を確認します。

### 検索条件と保存

簡易キーワード欄（`/`）もCtrl+Uで消去できます。Enterで検索を確定するまで通信しません。

`f`ではTab／Shift+Tab・上下で項目を移り、左右・Home／End・Backspace／Deleteで編集、Ctrl+Uで欄を消去します。日付は`YYYYMMDD`、終了日空欄は単日、期間は両端を含む最大30放送日です。地域は`全国`・`JP13,JP14`・`局:TBS`を直接入力できます。

地域・番組ジャンル・出演者分類の欄では`F2`で名称から複数選択できます。上下で移動、Spaceで切替、Enterでフォームに反映、Escで選択画面だけを取り消します。分類候補は編集開始時点で観測したものだけで、全分類ではありません。今回未観測の保存済みIDも保持します。IDの直接入力と軸別の未分類指定も使用できます。同じ軸の選択はOR、異なる条件はANDです。

フォームのEnterで検索を確定、Escで全編集を取り消します。入力・選択・取消では通信せず、確定時に新規取得します。検索中や失敗時も再生を継続し、古い結果で一覧を上書きしません。最後に確定した条件は正常終了時に保存します。

`b`で名前付き条件を開き、`n`で確定済み条件を保存（同名は更新）、`d`→`y`で削除、`r`で保存ファイルを再読込します。削除は`n`／Escで取消します。条件一覧のEnterは保存した日付・期間も含めてフォームへ呼び出すだけで、もう一度Enterで検索します。保存・削除・呼び出しだけでは通信や再生切替を行いません。

### 認証と再生

`I`でログイン入力を開き、Tabで欄移動、パスワード欄のEnterで送信、Escで取消します。パスワードは非表示・非保存です。認証成功後のセッションだけを原子的に保存します。`O`→`y`で再生を停止してローカルの保存セッションを削除し、`n`／Escで取り消します。CLIの`login`・`session`・`logout`も使用できます。

同じ`--data-dir`の保存セッションを起動時に非同期で確認し、契約情報を表示します。ファイルなし・破損・失効・通信失敗でも探索を継続できます。再生準備時にもセッション・契約・個別番組の配信条件を確認します。放送前は通信せず拒否し、準備失敗時は現在の音声を維持します。番組末尾で停止し、次番組へは移りません。ライブ再開は同じ枠の最新位置を取得します。

`g`は番組冒頭からの整数秒を入力し、Enterで確定、Escで取消します。入力中に別の再生対象へ変わった要求は拒否します。再生欄の「今回の出力」は現在の出力世代の秒数・不足フレーム数（秒換算）・PCM形式・セグメント数です。シーク／切替でリセットされ、聴取時間の累計ではありません。停止時の診断を保持し、エラー時の直近値は「終了時未集計」と表示します。

「処理診断」は現在の取得・復号・PCM配送待ちなどの段階と経過時間、取得最大・復号直近／最大・直近音声の長さを示します。実時間の計測で、CPU時間ではありません。配送待ち・配信更新待ちは取得や復号の最大値へ含めず、再生ワーカーの切替でリセットします。CLIの`status`と手動検証の進捗JSONでも確認できます。

停止・切替・準備取消は、ヘッダー待ちや本文受信中も取消を確認してHTTPの待機処理を破棄します。OSのDNS処理そのものは中断できませんが、最大4件に制限します。認証情報の更新中に終了して結果が未確認なら、CLIの`session`で保存状態を確認してください。

### チャプターと検証範囲

現在の確認済み範囲と残る項目は[検証一覧](docs/validation.md)を参照してください。日付ごとの詳細記録とは分けて整理しています。

`c`で対象番組の公式AIチャプターを取得し、上下・`j/k`で章を選択、`Tab`で要約欄を拡大し上下・ページ・Home/Endでスクロール（先頭1200文字まで）、もう一度`Tab`で章一覧へ戻り、`r`で再取得、Escで詳細へ戻ります。開き直しも新規取得し、取得中・未提供・失敗・対応付け未確認を区別します。イベント原点と放送枠の開始が一致する場合は、`Enter`で章の開始位置から再生します。同じ枠のタイムフリーならシーク、別枠やライブからはタイムフリーへ切り替えます。聴取可否と配信時刻を再確認し、準備失敗時は現在の再生を継続します。閲覧対象と再生対象が一致するときだけ`[再生位置]`を表示します。異なるイベント原点の補正は未対応です。対応付け未確認の場合は、イベント情報未確認・開始位置のずれ・放送枠の不一致を区別して表示します。

長時間検証は、30分以上残る枠を同じ出力世代で1800秒以上再生し、検索編集・取消・確定・再取得・画面切替・チャプター閲覧の応答、不足カウンター、停止と端末復元を確認します。シーク・停止／再開・切替の検証とは分けます。実施日・対象・結果と未検証の範囲は[実装状況](docs/implementation.md)に記録します。音声コールバックへの受け渡し量は聴感品質や機器遅延を保証しません。

明示実行用の検証スクリプト（macOS・Python 3標準ライブラリのみ）も利用できます。先にビルドし、有効な保存セッションと十分な長さのタイムフリー枠を指定してください。常にミュートし、実行ファイルを一時コピーするので検証中の再ビルドから分離されます。セッションも権限制限した一時コピーを使い、通常の検索条件を変更しません。検証用の子プロセスを親の制御端末から分離し、指定したPTYの描画寸法も確認します。

```sh
python3 scripts/verify_tui_playback.py \
  --session-file "$HOME/Library/Application Support/jp.radiko-client.radiko-client/session.json" \
  --station TBS --date 20261015 --start 20261015120000
```

日付・枠は聴取可能な対象へ変更してください。`--pause-seconds 1800 --seconds 30`で30分の一時停止中に位置保持・検索操作を確認し、再開後の出力も確認します（タイムフリー専用）。停止時間は連続出力秒数に含めません。`--seconds 60 --interval 3`は短時間の操作確認、`--live-end --date auto --start auto --station RN1`は実行時の放送中枠が30分以内に終了する場合の自然終了確認です。終了後のJSONに完了・不足数・端末復元・ビルドのハッシュを出します。Ctrl+Cで中断しても検証用プロセスと一時ファイルを片付けます。通常の`cargo test`では実行されません。

`--offset 1000 --seconds 120`で指定位置からミュート出力し、停止した音声位置の前後を短時間で確認できます（タイムフリー専用）。再生停止時には固定エラー分類とHTTP状態番号だけを記録し、通知本文やURLは出力しません。

出力秒数・不足・位置はフッターの既知の診断行から読み、番組本文やタイトルの数字は使いません。

通信診断は、応答待ち・本文受信・再試行待ちと最大時間を表示します。応答待ちはDNS・接続・TLSなどを含むため、サーバー待ちだけの時間ではありません。「試行」は要求開始数、「再試行待ち」は待機開始数で、待機中に取消した場合も含みます。高さ36行未満のTUIでは`?`の操作一覧から確認できます。検証JSONの`pipeline.http`には固定段階と数値だけを出します。

再生中の配信失敗は、固定の`error_kind`と`source_stage`（`segment`＝音声取得、`playlist`＝HLS一覧更新、`null`＝段階不明）で報告します。URL・署名・本文を診断JSONへ転記せず、直近のカウンターを終了時の最終集計とは区別します。

`--restart-check`は測定後の停止から、同じTUIで選択枠を冒頭から再生し直し、5秒以上の新しい出力世代を停止する確認です（タイムフリー専用）。本測定と再生し直しの秒数・不足は別に記録し、最後に正常終了と端末復元を確認します。

`--sleep-check --seconds 30`は操作者がMacをスリープ・復帰させる無音検証です。`sleep_ready`を確認してスリープし、復帰後に`awake`とEnterを入力します（待機上限10分）。停止と出力継続の両方を観測し、操作一覧の応答、明示的な再生し直し、その後の出力と端末復元を確認します。OSのスリープ操作や出力先変更はスクリプトから行いません。`--live-end`・`--device-check`・`--pause-seconds`とは併用できません。

`--device-check --seconds 30`は、既定の出力先にした外付け機器を操作者が切断・再接続する検証です。`device_ready`の`awaiting`が`disconnected`になったら切断後に同じ文字列とEnterを入力し、`reconnected`になったら再接続・出力先の確認後に同じ文字列とEnterを入力します。OSの出力先はスクリプトから変更しません。機器切断後のエラー／出力継続は観測結果として記録し、再接続後は明示的な再生要求と正常終了を確認します。各操作は10分以内に行います。

検証スクリプトの端末読み取り部分は`python3 -m unittest discover -s scripts -p 'test_*.py'`でオフライン確認できます（アカウント・実通信・音声出力なし）。


全国検索の実機負荷は、アカウントを使わない明示実行で計測できます。

```sh
python3 scripts/verify_tui_catalog.py --start 20260921 --end 20261020
```

指定した最大30日分を全国から新規取得します。番組データはメモリ内だけに保持し、取得件数・時間・地域／局・日の失敗件数・不正枠数・macOSの子プロセスのピークRSS・ヘルプ表示までの時間・端末復元を出力します。`--station TBS`で単局に絞って検証することもできます。計測にはPTYの読取待ちも含むため、描画だけのベンチマークとは異なります。取得中と完了後に一覧移動とヘルプを操作し、音声再生は行いません。通常のテストからは実行されません。

操作一覧では上下・`j/k`・`PageUp/PageDown`・`Home/End`でスクロールできます。小さい端末でも末尾まで閲覧できます。
